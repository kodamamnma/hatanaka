# CLAUDE.md — 作業ルール（全案件共通・原則書き換えない）

このファイルは **「どう振る舞うか」** だけを定義する。
案件固有の情報（クライアント名・配色・技術構成など）は一切書かず、すべて `README.md` に置く。

---

## 0. セッション開始時の手順

1. `README.md` を読む（案件の前提・仕様・現在地）
2. `history.md` の**上から5件**を読む（直近の経緯・未解決事項）
3. 不足があれば作業前に質問する。**推測で進めない**

---

## 1. 応答フォーマット

依頼を受けたら、次の4ブロックで整理してから着手する。

| ブロック | 内容 |
|---|---|
| 指示 | 何をするか（1行） |
| 前提 | README/historyから拾った関連情報 |
| 入力 | 読む・使うファイル、素材、参考サイト |
| 出力 | 生成・変更するファイルと、その完了条件 |

前提に不足・矛盾があれば、この段階で止めて確認する。

---

## 2. コードを書く前の禁止事項

- 対象ファイルを**読まずに**編集しない
- ファイル全体を書き直さない（該当箇所のみ差分で修正）
- `README.md` に無いライブラリ・CDN・フレームワークを勝手に追加しない
- 新しい色・フォント・余白の値を勝手に作らない（デザイントークンを使う）
- 依頼されていないリファクタリング・ファイル削除・構成変更をしない
- 本番環境・DB・公開ファイルへの破壊的操作は必ず確認を取る

---

## 3. 実装規約

### 共通
- 1回の依頼 = 1つの関心事。まとめて壊さない
- 既存のコードスタイル（インデント・命名・構造）に合わせる
- コメントは「なぜそうしたか」を書く。「何をしているか」は書かない

### HTML
- セクションごとに `<!-- ▼ セクション名 -->` 形式のコメントで区切る
- `h1` は1ページに1つ。見出しレベルを飛ばさない
- 画像には必ず `alt`。装飾画像は `alt=""`
- 更新担当が非エンジニアの場合、テキスト部分は編集しやすい平易な構造にする

### CSS
- デザイントークン（色・フォント・余白・角丸）は `:root` のCSS変数のみを使う
- クラス名は `block__element--modifier`（BEM）で統一
- **モバイルファースト**。`min-width` でPCを上書きする
- ブレークポイントは `README.md` の値のみ使用
- 1ファイルが長くなったらセクション単位で分割し、README の構成表を更新する

### JavaScript
- 素のJSで書けるものにライブラリを入れない
- DOM取得は存在チェックをしてから使う（他ページでのエラーを防ぐ）
- アニメーションは `prefers-reduced-motion` に配慮する

### SEO / パフォーマンス（全ページ必須）
- `title` / `meta description` / OGP / favicon
- 画像は WebP、`loading="lazy"`、`width`/`height` 指定
- リンク切れ・404の確認

---

## 4. 作業完了時の手続き（省略しない）

1. `history.md` の**先頭**に1エントリ追記（形式は history.md 冒頭の定義に従う）
2. 仕様・構成・トークンが変わったら `README.md` の該当セクションを上書き更新
3. 変更点を3行以内で報告し、**確認してほしい箇所**を明示する

---

## 5. 迷ったときの優先順位

1. クライアントの事業目的（README「サイトの目的」の優先順位）
2. 更新担当者の運用しやすさ
3. 表示速度・アクセシビリティ
4. 見た目の新しさ

---

## 6. 質問してよい／すべき場面

- 仕様がREADMEに無い、または矛盾している
- デザイン意図の解釈が2通り以上ある
- 影響範囲が依頼の外に及ぶ
- クライアント確認が必要な内容（文言・料金・実名）
